## Repo Guidance for Autobuild

- **Stack:** Static HTML/CSS/JS site served by GitHub Pages. No build step, no package manager, no test framework.
- **Default branch:** `gh-pages` (the live site branch).
- **Map library:** Mapbox.js v2.0.1 loaded via CDN (`api.tiles.mapbox.com/mapbox.js/v2.0.1`). Mapbox access token is hardcoded in `art.js`.
- **Data:** Art pieces stored as GeoJSON features in `art.geojson`. Each feature has properties: `url` (full image path), `image` (thumbnail path), `nav` (nav thumbnail path), `pieceID` (integer), `picnote` (text description), `icon` (icon config object), `marker-color`, `marker-size`.
- **Content scripts:** `add_image.py` and `replace_image.py` are **Python 2** scripts (`raw_input`, PIL `Image.ANTIALIAS`). They do not run on Python 3. Run manually with a Python 2 interpreter when editing content; not part of any pipeline.
- **Images:** Generated by the Python scripts into `images/`. Naming: `{pieceID}.jpg` (full), `{pieceID}_thumb.jpg` (thumbnail), `{pieceID}_icon.png` (map icon), `{pieceID}_nav.jpg` (nav thumbnail).
- **Lazy loading:** `lazysizes.min.js` lazy-loads nav thumbnails.
- **Custom domain:** `atlantaartmap.com` via `CNAME` file.
- **No lint, typecheck, or test commands** — static site with no tooling.

## Known upstream issue: basemap tiles

The map style `atlantaartmap.jnem740e` is a Mapbox "Classic" style. Mapbox has deprecated Classic styles: the tiles endpoint now returns HTTP 410 ("Classic styles are no longer supported"). This affects production (atlantaartmap.com) identically — it is not a local-environment problem. All app features except the base map (markers, clustering, popups, thumbnail nav, deep links) work because they run on local data (`art.geojson` + `images/`). Fixing the basemap requires migrating to a current Mapbox style — out of scope for setup.
